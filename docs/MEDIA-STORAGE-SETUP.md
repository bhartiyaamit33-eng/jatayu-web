# Media Storage Setup (Google Cloud Storage bucket)

How media works in this project and how to put it on a **Google Cloud Storage
(GCS)** bucket for the live Firebase App Hosting site.

> Companion docs:
> [FIREBASE-APP-HOSTING-SETUP.md](./FIREBASE-APP-HOSTING-SETUP.md) (fresh setup) ·
> [FIREBASE-DEPLOYMENT-PROCESS.md](./FIREBASE-DEPLOYMENT-PROCESS.md) (what we did).

---

## 1. How media works here (read this first)

Payload stores every media item as **two things**:

1. A **row in the Postgres database** (`media` table) — filename, `alt` text,
   `caption`, dimensions, and the list of generated sizes.
2. The **actual file(s)** in the storage backend (GCS bucket / Azure Blob / local disk).

**Consequence:** dropping files directly into the bucket does **NOT** make them
appear on the site. With no DB row, Payload doesn't know they exist. You must
upload through **`/admin` → Media**, which writes the file to the bucket **and**
creates the DB row in one step. The bucket is just the file store; the **database
is the source of truth**.

---

## 2. Where it's configured (which files)

| File | Role |
|---|---|
| `src/payload.config.ts` (lines ~60–98) | Chooses the storage backend from env vars. **This is the switch.** |
| `src/collections/Media.ts` | Upload rules: allowed types, required `alt`, and the image sizes generated. |
| `apphosting.yaml` | Where you set `GCS_BUCKET` for the live site. |

### The switch (`src/payload.config.ts`)
```
GCS_BUCKET set?                          → Google Cloud Storage  (collections: { media: true })
else NODE_ENV=production + Azure vars set → Azure Blob
else                                      → local disk (public/media)
```
On Cloud Run / App Hosting, GCS auth uses **Application Default Credentials (ADC)**
from the backend's service account — **no key file** is needed in production.
`GCS_PROJECT_ID` / `GCS_KEY_FILENAME` are only for local testing against a real bucket.

### Upload rules (`src/collections/Media.ts`)
- `slug: "media"`
- `mimeTypes: ["image/*"]` — images only.
- `alt` is **required** (accessibility); `caption` optional.
- `imageSizes`: `thumb` 320×240, `card` 800×600, `hero` 1600×900.
- `staticDir: "public/media"` is the **local-disk fallback only** — ignored once a
  cloud bucket is active.

## 3. Bucket structure

No prefix/folder is configured, so files land at the **root of the bucket**, named
by their filename. Each upload produces the **original + 3 resized variants**
(generated by `sharp`):

```
gs://YOUR_BUCKET/
├── xray.jpg                 # original
├── xray-320x240.jpg         # thumb
├── xray-800x600.jpg         # card
└── xray-1600x900.jpg        # hero
```

> Want everything under a folder like `media/…`? That requires adding a `prefix`
> to the `gcsStorage(...)` config in `payload.config.ts`. Not set today.

## 4. Enable GCS for the live site (step by step)

GCS is **not enabled yet** — the site currently deploys with the database only.
Do this on **Windows PowerShell** with `gcloud` + `firebase` installed.

### 4.1 Create the bucket
```powershell
gcloud storage buckets create gs://jatayu-media `
  --location=asia-south1 `
  --uniform-bucket-level-access `
  --project=YOUR_PROJECT_ID
```

### 4.2 Grant the App Hosting backend access
The backend runs as a Compute service account. Give it read/write on the bucket:
```powershell
# find the backend service account (Console → App Hosting → backend → Settings),
# usually:  PROJECT_NUMBER-compute@developer.gserviceaccount.com
gcloud storage buckets add-iam-policy-binding gs://jatayu-media `
  --member="serviceAccount:PROJECT_NUMBER-compute@developer.gserviceaccount.com" `
  --role="roles/storage.objectAdmin" `
  --project=YOUR_PROJECT_ID
```

### 4.3 Tell the app to use it (`apphosting.yaml`)
Add to the `env:` list:
```yaml
  - variable: GCS_BUCKET
    value: jatayu-media
    availability: [BUILD, RUNTIME]
  # optional, only if ADC can't infer the project:
  - variable: GCS_PROJECT_ID
    value: YOUR_PROJECT_ID
    availability: [BUILD, RUNTIME]
```

### 4.4 (Public images) make the bucket readable
If media should be publicly viewable on the website:
```powershell
gcloud storage buckets add-iam-policy-binding gs://jatayu-media `
  --member="allUsers" `
  --role="roles/storage.objectViewer" `
  --project=YOUR_PROJECT_ID
```
(Skip this if you intend to serve images through signed URLs / a CDN instead.)

### 4.5 Deploy
```powershell
git add apphosting.yaml
git commit -m "Enable GCS media storage"
git push                      # auto-deploys
# or:
firebase apphosting:rollouts:create YOUR_BACKEND_ID --git-branch main --project=YOUR_PROJECT_ID
```

### 4.6 Verify
- Go to `https://<your-site>/admin` → **Media** → upload an image.
- Confirm the object appears:
  ```powershell
  gcloud storage ls gs://jatayu-media
  ```
- Confirm it renders on the site where that media is used.

## 5. Local testing against a real bucket (optional)

In `.env.local`:
```dotenv
GCS_BUCKET=jatayu-media
GCS_PROJECT_ID=YOUR_PROJECT_ID
# either authenticate ADC:
#   gcloud auth application-default login
# or point at a service-account key:
GCS_KEY_FILENAME=C:\path\to\sa-key.json
```
Then `npm run dev` and upload via `/admin`.

## 6. Migrating existing media (Azure Blob → GCS)

Because the DB holds the records, a migration is **two parts**:

1. **Copy the files** from the old bucket/container to the new GCS bucket
   (e.g. `gcloud storage cp` / `azcopy` → `gcloud storage cp`), keeping the **same
   filenames** (including the `-320x240` etc. size variants).
2. **Keep the DB rows** — the `media` table already references those filenames, so
   if names are preserved and `GCS_BUCKET` is set, existing records resolve to the
   new bucket automatically.

If filenames change, the DB rows must be updated to match. Plan this as a
one-off script; don't hand-edit. (Ask if you want this scripted.)

## 7. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Uploaded image 403 / not visible on site | bucket not public and no signed URLs | §4.4, or serve via signed URLs |
| `Could not load the default credentials` | backend SA lacks access / ADC missing | §4.2 (grant `objectAdmin`); locally `gcloud auth application-default login` |
| Files in bucket but not in admin | no DB row (copied manually) | upload via `/admin`, or migrate rows (§6) |
| Still writing to `public/media` | `GCS_BUCKET` not set/visible at runtime | ensure it's in `apphosting.yaml` `env` and redeploy |
| Non-image rejected | `mimeTypes: ["image/*"]` | widen `mimeTypes` in `src/collections/Media.ts` if needed |
